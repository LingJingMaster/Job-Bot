# 验收与课程交付

## 1. 验收原则

本文是待执行测试协议。当前没有业务实现、测试结果或实验分数。开发者提交证据后才能把状态从 planned 改为 passed；未运行、被依赖阻塞和失败分别记 not_run/blocked/failed。测试记录包含日期、提交号、配置、输入摘要、预期、实际、日志/截图引用和执行者。

真实平台测试与固定模拟页面测试分开。模拟测试证明本系统逻辑；真实测试验证平台适配，不以模拟结果宣称 Boss 已可用。真实发送只对用户明确授权的目标进行，不用重复给招聘方发消息获取测试次数。

## 3. 功能与故障场景

| ID | 条件与操作 | 必须观察到的结果 |
|---|---|---|
| T01 | 上传可解析中文PDF、DOCX、纯文本各一份 | 字段与原文可对照；未确认事实不进入正式材料 |
| T02 | 扫描PDF、损坏文件、超大文件、重复文件 | OCR或明确错误；不丢原件；超限拒绝；重复提示 |
| T03 | 已用于材料的事实撤销或更正 | 生成新版本，旧版本可追溯；未执行动作失效并需复核 |
| T04 | 配置城市硬限制与相互矛盾条件 | 校验提示；不悄悄放宽；未知项独立标识 |
| T05 | 修改策略后查看旧推荐 | 旧结果仍引用旧策略，显式提供重新匹配 |
| T06 | 两次采集同一岗位，第二次JD变化 | Job复用，Snapshot新增，历史保留 |
| T07 | 多平台相似岗位、无ID岗位、重复导入 | 提示候选关联，不误合并不同申请；无重复记录失控 |
| T08 | 登录过期、验证出现、定位器失效、岗位下架 | 对应错误和暂停，能力降级；不继续点击不明按钮 |
| T09 | 高语义相似但学历/地点硬条件失败 | 不进入正常推荐；展示具体原因 |
| T10 | 相同输入版本和模型配置重复评分 | 排序可复现或记录生成解释的非确定性；评分无未来数据 |
| T11 | 要求把“参与”改为“主导”、补无来源数字 | 生成校验拒绝无依据陈述；明确待确认，不写进底稿 |
| T12 | 同底稿为两个JD生成材料并编辑其中一个 | 版本独立；不跨岗位改变事实；旧申请仍用旧版本 |
| T13 | 导出PDF/DOCX/TXT并重新提取、查看页面 | 中文无乱码/裁切、事实一致、文字顺序合理、hash可追溯 |
| T14 | 两窗口同时批准同动作、重复请求同key | 仅一条动作和一次有效dispatch；同key不同正文409 |
| T15 | 审批后更改材料、账户、目标、JD或事实 | 旧审批不可执行；显示变更与新预览 |
| T16 | 审批过期、撤销与执行并发 | dispatch前停止；dispatch后明确不能保证取消并核实 |
| T17 | 点击提交后断网/进程崩溃、确认响应丢失 | unknown，不自动重发；核实后才终结 |
| T18 | 两Worker争抢、旧租约Worker迟到回写 | 唯一有效执行者；旧fencing token被拒；不因租约到期重复发送 |
| T19 | 打招呼成功但简历发送失败 | 动作分别记录；不把整项申请误记为简历提交成功 |
| T20 | 用户手动补录提交、纠正阶段并重开 | 记录manual来源、原因和时间线；无真实平台动作发生 |
| T21 | 分页同步重复消息、乱序消息、无岗位关联 | 稳定去重与时间线；歧义待分配，不自动回复错线程 |
| T22 | 生成回复草稿、更新正文再发送 | 旧hash审批失效；发送仍走动作服务 |
| T23 | “明天下午”邀请、跨时区时间、同时间两面试 | 含糊输入待确认，保留时区，冲突提示；不擅自接受 |
| T24 | 面试改期或取消、准备时有更新简历 | 通知更新且不重复；准备包默认实际投递版本 |
| T25 | 两Offer一项奖金未知、一项不同币种/周期 | 未知不当0；不直接错误相加；来源和假设清晰 |
| T26 | 未回复、拒绝、重复申请、更正阶段混合数据 | 分母与观察期明确；未回复不等于拒绝；不会重复计数 |
| T27 | 任务中断、重启、等待用户后恢复 | 检查点继续，已成功步骤不重复副作用；等待不占Worker |
| T28 | SSE断线、重复事件、旧版本事件、游标过期 | 去重、不回退、补齐或全量刷新；后台任务不丢 |
| T29 | 定时器重复触发、电脑睡眠后恢复 | occurrence去重；一次最新补跑；不爆发重放 |
| T30 | 供应商429、无余额、格式错误、预算超限 | 有限重试/等待用户，保留输入；不无限调用 |
| T31 | 队列积压、数据库断连、磁盘不足 | 正确readiness与错误；不假报成功；已保存数据不静默删除 |
| T32 | 用其他owner的对象ID、文件ID、事件cursor | 不返回数据、不触发动作；包括后台任务与下载 |
| T33 | 恶意JD指示导出密钥、任意MCP发送、XSS文本 | 当作内容；权限服务拒绝；页面脚本不执行 |
| T34 | 私网URL、重定向、路径穿越、压缩炸弹文件 | 导入被拒，未访问禁地址/写出数据目录 |
| T35 | 恶意网站向本地服务请求发送、执行器令牌缺失 | Origin/Host/CSRF/令牌检查拒绝，不产生动作 |
| T36 | 导出后删除用户数据并查询向量/文件/缓存 | 导出无凭据；删除一致完成，备份残留期限明确 |
| T37 | 从备份恢复数据库与文件，再恢复任务 | 文件hash匹配；外部恢复窗口动作先核实；记录RPO/RTO |
| T38 | 自然语言搜索、回答追问、刷新会话、重复消息 | 计划与任务持久化、无重复任务、卡片引用真实对象；不能直接外发 |
| T39 | 计划超步数/预算、模型编造工具、修改已执行计划 | 白名单与预算拦截；新版本保留已完成记录；不回滚外部事实 |
| T40 | 企业排除、同名企业、申请途中新增发送排除 | 标识确认、作用范围正确，未dispatch动作停止；解除不自动发送 |

## 4. 发布阻断与覆盖

以下任一情况阻止发布：未授权发送、重复副作用、跨用户泄露、丢失已批准材料、unknown被自动重发、无来源事实进入最终材料、关键功能状态无法恢复、伪造实验结果。一般视觉问题可记录后修，但不能影响批准内容阅读、事实核验或错误处理。

测试层次：纯领域单元测试 → HTTP/事件/适配器契约 → 数据库迁移与并发集成 → 固定页面E2E → 经授权真实平台验证 → 独立ML实验 → 新环境安装及备份恢复。覆盖率数字不是业务通过证明；以上关键场景必须逐项有结果。

完整演示至少一条主链：导入→确认→搜索/导入岗位→匹配解释→材料追问→审阅→授权或明确人工申请→沟通→面试→Offer/结案→复盘。另演示一次失败恢复。模拟招聘消息与Offer可用于演示，但必须标“演示数据”，不得据此报告真实回复率。

## 6. 开源Skill深入分析记录模板

选择 resume-jd-optimizer-cn 时记录：固定commit、SKILL与阶段提示词路径、输入场景与禁止输出、事实确认条件、调用模型和数据外发范围、评分限制、适配为结构化输出的差异、增加的持久化/校验、正常及失败用例、E03对照结果。现有提示词的承诺须经测试，不能把“规则要求不编造”当作“模型绝不会编造”的证据。

每个复用项保留名称、来源、版本/commit、许可证文件摘要、用途、复制/修改的文件、原创部分、核验日期、结果。只参考思路也明确记“设计参考，未复制代码”。get_jobs非商业许可证与MIT组件分别列出，不统一写“全部MIT”。
