# 机器学习与材料生成

## 1. 能力与责任

机器学习核心为“个人经历与岗位的检索、匹配和排序”。大模型用于结构化提取、追问、基于证据的解释与材料草拟。规则程序负责权限、金额日期校验、状态转换、防重复和预算。任何模型输出都需 schema 校验，不能把自由文本当作工具授权。

匹配接口输入固定的 ProfileVersion、PreferenceVersion 与 JobSnapshot 集合；输出 MatchRun/MatchResult。材料接口输入目标岗位、已确认事实与材料类型；输出 MaterialVersion、Claim 引用、待回答问题和校验结果。接口字段见 [数据契约](02-contracts.md)。

## 2. 数据处理

1. 保留原始文档；提取文字与页码/段落定位。普通 PDF 先提取文本，扫描页标记需 OCR；OCR 结果带来源与未确认状态。
2. 按教育、工作、项目、技能切分；日期保留精度（月/年），不补不存在的起止日。项目成果与个人贡献分别存储。
3. JD 解析为职责、硬条件、技能、加分项；每项引用原文。模型推断的隐含要求只能标为推断，不能作为硬性淘汰条件。
4. 城市别名、技能别名使用版本化字典；如 Python 与 Python3 可关联，Java 与 JavaScript 不合并。原词保留。
5. 向量输入屏蔽电话、邮箱、姓名；分段长度由实际 tokenizer 测量，不能以字符数假定 token 数。超过上限按段处理并保存段索引。
6. 去重先用平台 ID，再用规范 URL、公司/职位/地点与文本相似度。跨平台近似重复仅提示候选关联，不自动合并不同申请。

解析结果必须通过类型、枚举、引用有效性与原文支持检查。JSON 解析失败可进行一次格式修复；仍失败返回待人工输入，不无限重试。

## 3. 检索与排序方案

### 3.1 基线 B0

在训练分区或事先冻结的检索语料上拟合字符 2—4 gram TF-IDF，以余弦相似度检索；同一评估内固定候选池。中文字符 n-gram 避免把分词库差异作为隐藏变量。保存词表、IDF、预处理配置及语料摘要。

硬条件先做三值判断 pass/fail/needs_review。默认列表只对 pass 正常排序，needs_review 单独分组供用户确认，fail 可在解释视图查看原因。所有模型比较使用相同硬过滤政策，并另外报告过滤误杀。

### 3.2 语义版本 B1

使用经中文样例验证的文本 embedding，按“职责与项目经历”“技能与技能证据”分组计算相似度。开发阶段由 WP04 选择并锁定模型、revision、tokenizer、维度、归一化规则及许可证；不预先将未经测试的型号宣传为最佳。

首个验证候选指定为 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)，发布者模型卡标注中文与MIT。选择它是便于开展本地中文表示实验的起点，并非已证明优于其他模型。WP04固定模型仓库revision后记录实际输出维度、最大输入长度和query instruction规则；若本机资源或测试质量不满足，提交模型替换记录并重跑同一验证集。B0使用 [scikit-learn TfidfVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html)，配置明确为 analyzer=char、ngram_range=(2,4)、norm=l2，其他参数也必须写入run-config。

向量检索先用精确余弦搜索作为正确性基准；岗位超过本地目标规模且实测需要时再启用近似索引，并测 Recall@K 相对精确检索的损失。模型升级重建对应版本向量，查询不得混用新旧空间。

### 3.3 综合版本 B2

初始排序分由独立、可解释的归一化特征组成：语义匹配、技能证据覆盖、职责相关度、软偏好满足度。建议初始权重 0.45/0.25/0.20/0.10，仅用于验证集起点，最终权重由验证集选择并在测试前冻结。缺失偏好特征重归一化并显示缺失，不能用零代表不满足。

技能覆盖分母为 JD 已明确且有权重的技能要求，分子是被已确认事实支持的要求；相同事实可以支持多项要求，但不得凭重复出现提高权重。硬性不满足不能被高语义分抵消。

标注量允许时，增加逻辑回归或轻量排序模型作为 B3，对上述特征训练。训练模型与规则混合版本分别命名；未训练时不能写“系统已学习用户偏好”。选择 B3 不是完成范围的前提，B0/B1/B2 的实质配置、比较和验证是必做。

## 4. 解释与事实边界

匹配解释输入结构化特征与已选证据，不让解释模型自行重新评分。输出包含匹配点、明确差距、未知项和原文引用。证据引用错误的解释不展示，退回结构化模板。

不得从“参与项目”推成“独立负责”，也不得从工具名称推断实际使用经验。用户确认的估算必须保留估算标记与来源。底稿更新后，旧匹配结果标为旧版，可查看但需重算后用于新申请判断。

用户拒绝推荐时记录原因：地点、待遇、岗位职责、企业、经验门槛、重复、其他。未点击/未回复不作为负样本。早期反馈仅修改显式偏好或生成可确认建议；累计数据足够后才能做离线个性化实验。保留时间切分，防止使用未来反馈训练过去推荐。

## 5. 简历优化流水线

可参考 resume-jd-optimizer-cn 的提示词与审查思路；它是待核验资源，不是现成后端服务。集成方需把工作流转换成可暂停、可追溯的业务步骤。

| 步骤 | 输入 | 输出与门槛 |
|---|---|---|
| 解析目标 | JD 快照 | 有原文引用的要求清单 |
| 证据映射 | 要求、确认事实 | covered/weak/missing/not_applicable；每项关联事实 |
| 缺口追问 | 重要 weak/missing 项 | 每轮最多 5 个具体问题；用户可跳过，跳过不补造事实 |
| 更新底稿 | 用户回答 | candidate FactRevision，经确认进入新档案版本 |
| 草拟材料 | 固定档案版本与 JD | 内容、claims、版本与模板摘要 |
| 校验 | 草稿与事实 | 数字、日期、公司、技能、贡献动词检查；无来源事实阻止批准 |
| 审阅与导出 | verified 材料 | 用户 approved 版本与 PDF/DOCX/TXT；导出 hash 绑定正文版本 |
| 面试准备 | 实际投递版本 | 针对个人贡献、方法、数据来源的追问；不以新版本替代历史版本 |

真实性检查采用确定性检查与语义审查结合：数字/专名差异检测、事实引用完整性、贡献动词与事实类型相容性、时间线冲突。模型审查只能作为辅助，不能保证语义蕴含完全正确；疑点交用户处理。

导出模板优先单栏、标准标题、可选中文字体嵌入；PDF 应可复制文字，DOCX 保留可编辑段落。导出后验证页数、乱码、裁切与文本顺序。ATS 可读性只描述结构检查，不保证特定招聘系统通过。

## 6. 模型网关与预算

模型服务提供 extract、embed、explain、draft、review 五类能力，调用记录保存模型版本、prompt/template hash、输入引用、token 用量、耗时、供应商 request_id 和结果状态；原始敏感正文不进普通日志。

模型返回结构化内容后执行 schema 与事实检查。读取任务遇到暂时网络错误最多重试 2 次并退避；生成总调用数受任务预算限制，重试也计入。提供方 429 遵循 Retry-After；无余额转 waiting_user。更换模型不得悄悄改写旧实验结果。

费用记录分 actual/estimated/unavailable；价格带来源和日期。预算预留只是估算，完成后按实际用量结算，超过上限停止后续步骤。用户选择云模型前明确哪些档案字段会发送；可选择脱敏输入，但应说明可能影响效果。

## 7. 数据集与实验协议

### 7.1 数据来源与标注

目标采集至少 30 份有授权的脱敏求职档案、300 个有来源的岗位快照；为每档案构造至少 30 个候选岗位，包含明显合适、语义接近但硬条件不符、关键词相近但职责不同的难例。数量是计划目标，不是已有数据。若无法达到，记录实际规模和统计局限，不用模型虚构真实样本。

人工标注 0=不合适、1=部分相关且关键条件待确认、2=基本合适、3=高度相关，同时记录硬条件标签与依据。至少 20% 样本双人独立标注，报告加权一致性及分歧处理；只有一个标注者时如实说明，并用间隔复标检查稳定性。

同一简历的修订属于同一 profile_group；同一岗位的近重复快照属于同一 job_group。训练/验证/测试按分组划分约 60/20/20，禁止同组跨分区。若 profile-job 连通关系使双向隔离难以成立，应分别设计“新用户”与“新岗位”测试并明确泛化对象，不能假装已同时满足两种隔离。

### 7.2 实验

- E01：B0、B1、B2 在相同候选池上比较；B3 若训练则额外列出。
- E02：B2 去掉语义特征、去掉技能证据特征，各做消融；其他因素固定。
- E03：相同基础模型下，普通润色与完整证据流水线比较；盲评顺序随机化。
- E04：人工操作与 Agent 工作流完成相同任务，采用配对设计并交换顺序；实际对外发送不作为随意重复实验对象。

排序指标 NDCG@10、Precision@10、硬条件误放行率/误杀率，另报 needs_review 比例。P@10 以标签≥2 为相关；候选不足10时用 min(10,n) 作分母并单列该组。NDCG 增益用 2^label−1；无相关项的查询单列，不以0或1悄悄混入均值。

简历指标：无事实支持陈述数/全部事实陈述数、重要要求证据覆盖率、人工修改比例、盲评质量。无法解析样本计入失败率，不从分母删除。模型自评分不得作为独立证据。

流程指标：目标任务完成率、人工操作时间、总耗时、重试次数、成本、人工接管率。任务“完成”由预先定义终态决定，不能把已开始或生成草稿算作已投递。

### 7.3 统计与发布

固定分组划分、种子、模型版本、依赖锁、参数、输入快照摘要。先在验证集选参数，再锁定测试集运行；测试集只用于最终比较，不反复调参。按用户/查询分组 bootstrap 估计95%置信区间，不能把同一用户的所有配对当独立样本。

设计目标：B2 在独立测试集的 NDCG@10 高于 B0，同时硬条件误放行不恶化；无事实支持的最终批准陈述在固定验收集为0。结果不达标也必须报告，不允许删除难例。业务可以回退已验证基线，研究结论如实记录。

每次实验产物：dataset-manifest、split-manifest、model-manifest、run-config、per-query-results、metrics、error-cases、环境记录。文件格式由 WP00 冻结；必须能从逐条结果重新计算汇总。
