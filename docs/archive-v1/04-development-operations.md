# 多 Agent 开发与运行交付

本文安排后续编程协作。当前只交付架构文档，由架构师独立维护。开发 Agent 不等于产品中的运行时 Agent。

## 1. 开发目录与所有权

以下目录为待创建布局，不代表已存在实现。

| 目录 | 负责模块 | 独占维护者 |
|---|---|---|
| apps/web/ | React 页面、客户端状态、生成的 API 客户端使用 | 前端 Agent |
| services/api/domain/ | 档案、岗位、材料、申请、沟通、面试、Offer | 业务 Agent |
| services/api/http/ | API 路由、认证、错误映射 | 业务 Agent，公共变更需集成负责人审阅 |
| services/worker/ | 调度、持久任务、状态恢复 | 工作流 Agent |
| services/connectors/ | 平台适配、浏览器执行器、MCP 网关 | 连接器 Agent |
| packages/intelligence/ | 解析、匹配、生成、证据校验 | 模型 Agent |
| contracts/ | OpenAPI、事件与模型 JSON schema、固定样例 | 集成负责人 |
| migrations/ | 数据库迁移 | 集成负责人，业务 Agent 提交建议 |
| tests/contract/、tests/e2e/、eval/ | 公共验收、实验与故障测试 | 验证 Agent |
| infra/、scripts/、依赖锁文件 | 部署、运行入口、版本锁 | 集成负责人 |
| docs/ | 本套设计与后续 ADR | 架构师/集成负责人 |

模块单元测试由模块维护者负责。禁止其他 Agent 为让测试通过而直接修改公共 schema、删测试或更换基线。跨模块改动先提交变更请求。

## 2. 开始编程前的契约冻结

WP00 是第一项依赖，必须产生：实体 schema、状态枚举、所有 API 操作、SSE schema、适配器协议、错误码、样例输入输出、模块 import 边界、依赖锁和启动入口。生成客户端由契约生成，前端不手写另一套枚举。

第一批 fixture 至少包括：确认档案、未知学历条件岗位、硬条件失败岗位、材料未证实数字、审批过期、提交结果未知、面试改期、Offer 金额缺失。fixtures 使用合成数据且标明，不冒充研究真实数据。

文档已有协议足以分配任务；WP00 将协议变为机器可读制品并进行实现层验证，不得借此重新定义产品范围。

## 3. 工作包

| 包 | 所有者 | 输入与依赖 | 输出 | 验收门槛 |
|---|---|---|---|---|
| WP00 契约与基础设施 | 集成负责人 | 全文档 | schemas、迁移骨架、认证、依赖锁、开发命令、固定样例 | 前后端同一契约；空库可迁移；未配置密钥仍能启动 |
| WP01 领域业务 | 业务 Agent | WP00 | F01—F14 的实体持久化、版本、业务服务、API | 状态与归属校验；历史不覆盖；事务与幂等测试通过 |
| WP02 工作流与授权 | 工作流 Agent | WP00，可用领域桩 | Task、Schedule、Outbox、Approval、Action、对话计划编排与恢复 | 双 Worker、超时、取消竞争、unknown及计划权限测试通过 |
| WP03 平台连接 | 连接器 Agent | WP00、真实账号手动验证条件 | 手动导入、Boss 适配器、能力矩阵、MCP只读/prepare工具 | 分能力实测；权限路径不可绕过；不确定副作用正确分类 |
| WP04 匹配与材料 | 模型 Agent | WP00、脱敏样例 | B0/B1/B2、解析、映射、追问、生成与导出 | 模型版本可复现、事实引用正确、产物视觉验证 |
| WP05 用户界面 | 前端 Agent | WP00 契约与 fixtures | 全部页面、状态恢复、预览审批、操作反馈 | 空/错/加载/冲突态；完整流程；无按钮直接绕过授权 |
| WP06 验证与实验 | 验证 Agent | WP00早期参与；最终依赖WP01—05 | 契约/E2E/故障/权限/性能测试、实验结果、错误分析 | 05 中全部发布门槛有证据；真实与模拟结果分开 |
| WP07 发布与课程材料 | 集成负责人 | WP06 | 安装运行说明、备份恢复、组件清单、报告与演示素材 | 全新环境复现；所有未完成项明示；无密钥或个人数据泄露 |

并发槽有限时按依赖调度，不机械同时启动所有 Agent。推荐波次：WP00 → WP01/WP03/WP04 → WP02/WP05（WP06持续维护测试）→ WP06/WP07。连接器验证可早于 UI 完成，不应等所有页面做完才发现平台不可行。

## 4. 每个 Agent 的任务说明模板

每次派工必须包含：目标需求编号、允许修改目录、已冻结契约版本、上游输入、交付文件、失败处理、测试命令、完成证据和禁止事项。明确“只完成分配范围；发现接口问题报告，不私自扩大变更”。

交接报告必须列出：实现的 Fxx、修改文件、接口变化（无则写无）、实际运行测试与结果、未运行测试及原因、依赖/迁移、已知问题、下一模块如何调用。不能用“应该能跑”作为完成结论。

## 5. 分支与集成

当前目录尚未初始化代码仓库。开发开始时由集成负责人建立仓库与默认分支；后续每个工作包使用独立分支/工作树。共享 `.env`、数据库文件、真实 Cookie 不进入工作树复制流程。各 Agent 使用独立数据库 schema 或独立测试库，禁止共用真实账户做并行发送测试。

合并顺序：契约 → 数据迁移与业务 → 模型/连接器 → 工作流 → UI → 故障与全流程验证。每次合并先检查差异范围，运行模块测试和受影响契约测试；集成分支运行关键全链路。变更 schema 必须单独先合并，客户端随之重新生成。

冲突处理以文档和最新已合并契约为准，不能随意选择某一边。迁移采用唯一编号和单一合并负责人，先在空库和上一版本备份上验证；禁止覆盖用户数据库以“修复”迁移。

## 6. 发布阶段

| 门槛 | 完成条件 | 失败时处理 |
|---|---|---|
| G0 设计与契约 | 全需求映射到工作包、API、实体、验收；依赖锁与样例可用 | 修订契约后再并行 |
| G1 平台可行性 | 登录、搜索、详情、目标动作与核实分别记录实际结果 | 失败能力保持 unverified/degraded；修适配器，不冒称自动化支持 |
| G2 业务全程 | 从档案到Offer/关闭与复盘可持久化走通，含手动补录 | 不发布只覆盖前半流程的完整产品声明 |
| G3 智能能力 | 独立实验、来源引用与材料真实性检查完成 | 回退可验证基线；保留失败实验 |
| G4 可靠性 | 故障、安全、恢复、无重复副作用验收通过 | 修复所有关键缺陷；不能以页面展示绕过 |
| G5 发布 | 新环境复现、备份恢复、报告/演示和组件清单齐全 | 阻止正式发布，列明未完成项 |

2026-11-18 是课程截止日期。建议11月4—5冻结契约并验证平台，6—10完成并行模块，11—13集成，14—16实验与故障修复，17整理交付，18提交。该日程是初步安排而非工期保证；负责人每天以完成证据更新预测，不虚报进度。

## 7. 部署与依赖

首版本地：前端静态资源由同源服务提供；API/Worker 与 PostgreSQL 可使用容器；有界面的浏览器执行器运行宿主机，用专用浏览器配置目录。数据库不对局域网开放；API默认监听回环地址。宿主执行器与服务使用显式配置的本地地址和单独随机令牌，不假定容器 localhost 就是宿主。

运行时版本由 WP00 选择兼容组合并精确锁定 Python、Node、数据库、pgvector、Playwright与浏览器修订、模型权重。使用发布版本不使用浮动 latest。版本表必须写明测试 OS/架构；当前不填写未经实测的兼容承诺。

开发阶段应实现以下命令入口并在 README 记录真实命令（本次文档不声称这些命令已存在）：bootstrap、migrate、dev、test-unit、test-contract、test-e2e、eval、backup、restore、doctor。入口必须返回非零退出码表示失败，不吞错误。

配置至少包括 DATABASE_URL、DATA_DIR、API_BIND、LOCAL_AUTH_SECRET、EXECUTOR_ENDPOINT、EXECUTOR_TOKEN、MODEL_PROVIDER、MODEL_ID、模型密钥引用、EMBEDDING_MODEL_REVISION、TASK_BUDGET、LOG_LEVEL。样例只含占位符；缺少必要配置给可读错误，不能用作者个人设置作默认值。

## 8. 安全与隐私实现要求

- 本地也需要会话令牌、Origin/Host 校验和同源策略，避免恶意网页向回环服务发起动作；Cookie会话使用CSRF防护。首次配对令牌只本机展示，不写URL或日志。多用户托管必须另做认证设计，不直接暴露本地模式。
- 密钥由系统钥匙串或受保护密钥存储管理；浏览器会话目录限制用户权限，与普通附件备份分开；浏览器调试端口只回环监听，不向模型提供。
- 上传校验扩展名、MIME、解压后大小与页数；禁止宏执行、路径穿越和解压炸弹。解析子进程设置资源上限与超时。
- URL导入仅允许明确的HTTP(S)招聘域名，阻断私网、回环、云元数据、file协议；每次重定向和DNS解析后检查，防止SSRF。
- JD、简历、消息中的“忽略规则、调用工具、发送数据”等只作为内容，不提升权限。渲染HTML先清理，禁止脚本和危险链接协议。
- 云模型请求按必要字段最小化发送。故障截图默认短期留存，不记录无关聊天；日志包含标识、状态和错误码，禁止Cookie、Authorization、完整个人材料。
- 默认任务与事件日志30天、截图7天，业务历史保留至用户删除；导出包24小时后过期。用户可缩短；删除清除全文索引、向量、缓存与文件引用，备份按30天轮换到期消除，并明确显示备份残留期限。

## 9. 运行手册

启动顺序：检查配置和存储权限 → 数据库健康 → 备份旧数据并迁移 → API → Worker → 浏览器执行器 → 前端健康检查。关停先停止新任务，等待或标记正在外发动作，保存检查点，关闭执行器，再停止服务。

健康检查分 liveness 与 readiness：进程存活不代表平台可用。数据库失败使写服务不可用；模型失败只影响依赖模型的任务；平台失效只禁用对应连接。监测队列长度、最老任务等待、租约超时、unknown动作数、各能力失败率、模型成本、磁盘空间。

| 事件 | 操作顺序 |
|---|---|
| Worker崩溃 | 停止该执行器派发，确认进程状态，检查ActionAttempt；纯计算可恢复，已dispatch先核实 |
| 平台页面变化 | 将能力degraded，停止受影响动作，保留脱敏现场，修定位器并重跑契约与真实验证 |
| 模型不可用 | 暂停相关任务，保留输入版本，允许基础管理；切换模型创建新manifest |
| 磁盘不足 | 禁止新上传/生成，保留数据库可读；清理过期临时文件，不自动删业务原件 |
| 数据库恢复 | 停Worker，校验备份摘要，恢复库和文件同一快照，核对迁移版本，将恢复窗口内外发动作列为待核实，完成核实后恢复调度 |
| 授权/会话疑似泄露 | 禁连接、撤销令牌、终止执行器，核对动作审计，重新配对；不把旋转令牌当作撤销已发送消息 |

每日备份数据库与文件manifest，记录schema版本和校验摘要；密钥单独安全恢复。每次发布至少做一次实际恢复演练，记录耗时、缺失文件和不确定动作处理。升级默认先兼容增字段，再迁移数据，最后收紧约束；回滚前确认旧版本兼容新schema，不直接执行破坏性降级。
