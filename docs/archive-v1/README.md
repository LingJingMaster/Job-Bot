# Job-Bot 开发文档

版本：1.0；编写日期：2026-11-04；状态：开发设计基线，尚未实施或实测。

目标是构建覆盖个人求职全过程的应用。本文档由架构师独立编写，供后续多 Agent 编程使用。本轮交付只有文档；这里描述的功能、指标和部署流程是待实现要求，不代表已有运行结果。

## 文档使用规则

- 产品范围以 01 为准，字段、状态及接口以 02 为准，模型评估以 03 为准。任何冲突必须修正文档后继续，开发者不得自行选择有利版本。
- 每个需求有 `Fxx` 编号，每个开发任务包有 `WPxx` 编号，每个验收场景有 `Txx` 编号。
- 后续实现必须生成机器可读 OpenAPI、数据库迁移和契约测试。本次不以未运行的程序代替设计文档。
- 后续的“多 Agent”指开发协作。产品运行时采用一个受约束的任务编排器调用能力模块，不要求建立多个互相对话的自主 Agent。
- 默认方案：个人本地部署、中文求职、Boss 为首个需要验证的招聘平台；前端 TypeScript，业务与模型 Python。多用户托管、收费 SaaS、招聘者端不属于本版本范围。
- 完整范围包括从档案到 Offer 和复盘。平台自动化有独立能力开关；手动导入或回填必须明确标识，不得冒充已支持平台自动化。
- 不把截止时间当作删除功能的理由。若真实平台验证未过，保留需求、记录未完成项；课程交付如需缩小范围，须由项目负责人明确决定。

## 不可破坏的规则

1. 已确认事实底稿与模型生成文本分开保存。
2. 外部发送授权绑定账户、目标、正文、材料版本和内容摘要；内容变化使旧授权失效。
3. 外部提交结果不确定时进入 `unknown`，先核实，不自动再次发送。
4. 用户归属检查覆盖每个对象、文件、事件和后台任务；模型不能授予权限。
5. 匹配分不表示录用概率；实验结果必须来自可复查记录。
6. 原始来源、材料版本、模型版本和操作证据可追溯。
7. 对外动作须经策略服务检查，不能通过 MCP 或直接工具调用绕过。
8. 所有可变版本和实验阈值必须在开发或实验前锁定；没有实测的能力标为未验证。

## 文档交付边界

这里已定义完整功能框架与实施协议。招聘网站当前 DOM、账号权限、页面行为、模型在本地机器的速度和成本，需要开发阶段获得运行证据。它们是明确的实施验证任务，不是本次文档已证明的事实。
