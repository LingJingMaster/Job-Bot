# 工作包、排期与协作

“开发者”指任何接手编码、数据、实验或写作的人或 AI；运行时产品**不是**多 Agent 系统。项目负责人（用户）对所有交付拥有最终决定权，并须能解释自己提交的设计与代码，因此**逐模块交付、逐模块评审**，不一次性生成整个仓库。

## 1. 优先级

| 级别 | 内容 | 说明 |
|---|---|---|
| **P0 必须** | 采集（Boss 或导入兜底）、简历事实确认、JD 解析、B0/B1/B2、标注与 E1、材料流水线含校验器、E3、E5（最小版）、端到端演示、可复现仓库、报告 | 缺任何一项，评分表的某一大项会失去支撑 |
| **P1 应该** | B3（训练）、E1a 消融、E2 抽取评估、E4 效率、申请跟踪看板、PDF 导出 | 时间允许则做；B3 强烈建议保留（课程“训练”证据） |
| **P2 可选** | 模式 B 自动点击、LightGBM、岗位聚类、解释的 LLM 改写、数据清除之外的管理功能 | 主线完成并已冻结实验后才开始 |

**落后时的砍项顺序**：P2 全部 → 模式 B → PDF（保留 DOCX/TXT）→ E4 → E2 → 申请看板 → E1a。**不得砍**：只读采集的安全检查、事实确认、校验器、E1、E3、E5。

## 5. 集成规则

- Git：每个工作包独立分支，合并顺序 **契约 → 数据与 LLM → 采集/解析 → 匹配/材料 → 界面 → 实验**。合并前检查差异范围，运行模块测试与受影响的契约测试。
- `.env`、`data/`、浏览器配置目录、真实简历/JD、缓存中的原文**一律 gitignore**；提交前运行 `scripts/check_secrets.sh`（扫描 Key、Cookie 样式字符串、`data/` 误入）。
- 禁止为让测试通过而修改契约、删测试或更换基线；发现接口问题提变更请求。
- 不同开发者使用各自的 `DATA_DIR`；**不并行使用同一 Boss 账号做采集测试**。
