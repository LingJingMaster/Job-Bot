# 机器学习方法与评估协议

本文是课程评分中“机器学习方法 20 分”与“实验评估 20 分”的实施依据。所有数量和阈值是**计划**；实际规模、结果与偏离须如实写入报告。

## 1. 模型在系统中的位置

| 环节 | 方法 | 类型 | 对任务的贡献 |
|---|---|---|---|
| JD/简历抽取 | LLM + schema 校验 + 原文引用校验 | 信息抽取（预训练模型调用） | 把非结构化文本变成可比较的要求/事实 |
| 岗位–档案匹配排序 | B0 TF-IDF → B1 embedding → B2 特征加权 → **B3 训练的逻辑回归** | 文本表示、检索、监督学习 | 决定先看哪些岗位 |
| 要求–证据映射 | embedding 相似度初筛 + LLM 判定 + 规则 | 检索 + 分类 | 找出缺口并指导追问 |
| 简历事实校验器 | 规则 + embedding + LLM 审查 | 二分类 | 阻止无依据陈述进入终稿 |
| （可选）岗位聚类 | KMeans / HDBSCAN on JD embedding | 无监督 | 岗位族与技能缺口可视化；仅在主线完成后做 |

**说明**：纯调用通用 LLM 不满足课程对“机器学习组件”的要求。本项目的 ML 实质是 B0–B3 的表示、特征、训练与比较，以及校验器的分类评估；LLM 作为抽取器/生成器被评估，而不是被当作成果。

## 2. 数据处理

1. **简历**：保留原文件；提取文本与页码/段落定位；按教育/工作/项目/技能切分为事实；日期保留精度；项目成果与个人贡献分开存储。
2. **JD**：保留完整原文与快照时间；LLM 解析为要求列表（§03-5.2），每项带原文区间；`inferred=true` 的项只作软信号。
3. **别名字典**（版本化 JSON，`src/jobbot/jobs/aliases.json`）：城市别名（“北京市/北京”）、技能别名（Python≈Python3；**Java≠JavaScript**）；原词保留。
4. **向量输入**：对档案文本与 JD 文本去除电话、邮箱、姓名；长度由实际 tokenizer 测量；超限按段切分，保存段索引，段间取 max（或按实验在验证上选 mean/max，记录选择）。
5. **去重**：平台 ID 优先；无 ID 时用规范 URL 或“公司+岗位+地点”+ 文本相似度，只提示候选关联，不自动合并。
6. **JD 质量门**：描述长度 < 50 字、无任何要求可抽取 → 标 `low_quality`，不进入评估池，计入采集质量统计（不从分母删除）。

## 3. 匹配方法

### 3.1 硬条件（所有方法共用）

三值判定 `pass / fail / needs_review`，依据：城市、学历、经验年限、薪资下限、排除词。未知字段按偏好的 `unknown_policy`（默认 `needs_review`）。**所有方法使用同一硬过滤政策**，另报硬条件误放行与误杀率。

### 3.2 方法

| 方法 | 定义 | 参数（须写入 run-config） |
|---|---|---|
| **B0** | 字符 n-gram TF-IDF，档案文本 vs JD 文本余弦。`TfidfVectorizer(analyzer="char", ngram_range=(2,4), norm="l2", sublinear_tf=?, min_df=?)` | 词表在**训练分区岗位语料**上拟合并保存；未列出的参数写默认值也要记录；scikit-learn 版本 |
| **B1** | `BAAI/bge-small-zh-v1.5` 向量，余弦。起始候选，非“已证最优” | 模型 revision、输出维度、最大长度、是否加 query 指令、归一化、分段聚合；WP-D 先在**训练/验证 profile** 上比较有无指令后锁定 |
| **B2** | 加权和：`0.45·f_sem + 0.25·f_skill + 0.20·f_resp + 0.10·f_pref`（初始值）；缺失偏好特征按剩余权重重归一并标注，**不以 0 代表不满足** | 权重由训练 profile 上网格搜索（步长 0.05，目标 NDCG@10）选定后冻结 |
| **B3** | 逻辑回归（L2）预测 `rating ≥ 2`，输入 §3.3 全部特征 + `f_tfidf`；`C` 由训练 profile 内层交叉验证选取；特征标准化只在训练集拟合 | 随机种子、`C`、训练 profile 列表、特征顺序、sklearn 版本。标注足够时可加 LightGBM LambdaRank 作为 B3b（可选） |
| **L0**（基线） | 纯 LLM：给定确认事实与 JD 原文，输出 0–3 评分与理由（`temperature=0`，JSON schema），不使用上述特征 | 模型、提示模板哈希；缓存记录 |
| **H0**（人工基线） | 项目负责人手工筛选的耗时与决策（E4） | — |

> B3 才是“训练”。未训练时不得写“系统学习了用户偏好”。若标注量不足以训练（总标注 < 150），B3 降级为“方向性实验”，如实说明。

### 3.3 特征（均在 [0,1]，**不使用依赖候选池的归一化**，避免跨运行漂移）

| 特征 | 计算 |
|---|---|
| `f_sem` | 档案全文向量与 JD 全文向量余弦，线性映射到 [0,1] |
| `f_skill` | JD 中 `core_skill` 要求（权重 w）：被确认事实的技能（经别名字典）支持者记 1，否则 0；`Σw·hit / Σw`；无此类要求→ 缺失（重归一） |
| `f_resp` | 每条 `responsibility` 要求取其与确认事实向量的最大余弦，再按权重平均 |
| `f_pref` | 软偏好满足度：薪资区间重叠、偏好城市、偏好关键词；缺失项不计 |
| `f_tfidf` | B0 得分 |
| `f_exp` | 经验/学历差值的有界变换（用于 B3） |

同一事实支持多项要求允许，但不因重复出现提高权重；硬条件 `fail` 不能被高语义分抵消（分组展示）。

### 3.4 解释与事实边界

解释模块输入**结构化特征和已选证据**，不得重新评分。输出：匹配点、明确差距、未知项，均带引用（事实 ID 或 JD 区间）。引用校验失败 → 退回模板文字（“与该岗位 X 项要求匹配度较高：…”）。不得把“参与”说成“独立负责”，不得从工具名推断使用深度。

## 4. 简历定制流水线

| 步骤 | 输入 | 输出与门槛 |
|---|---|---|
| 1 解析 JD | 快照 | `JDParse`（已存在则复用） |
| 2 证据映射 | 要求 + 确认事实 | `EvidenceLink[]`（schema 见 03-5.3） |
| 3 缺口追问 | 权重 ≥ 2 且 weak/missing | ≤ 5 题；每题指向具体要求；跳过不补造 |
| 4 更新底稿 | 用户回答 | 候选事实 → 用户确认 → 新 ProfileSnapshot |
| 5 草拟 | 固定快照 + 映射 | 分段 bullet，每条带 `fact_ids` |
| 6 校验 | 草稿 + 事实 | `ClaimCheck[]`；未通过者不可批准 |
| 7 审阅导出 | verified 材料 | 用户编辑→批准→DOCX/PDF/TXT；导出文件的 hash 绑定正文版本 |

**复用 resume-jd-optimizer-cn（MIT，commit `114c85c`）**：其 `prompts/`（`jd_parser`、`gap_analyzer`、`experience_interviewer`、`resume_rewriter`、`risk_checker` 等）与 `docs/resume_truthfulness_policy.md` 的真实性规则（`已确认/待确认/模型推断`三态、贡献动词证据标准“以最低已确认证据为准”）作为提示词与审查规则的起点。**本项目的适配**：

- 其输出是对话式长文本；我们改写为 JSON schema 输出，并增加持久化、引用校验和确定性校验（它没有）。
- 其评分表（`rubrics/*`）是 LLM 打分，无标注依据；本项目**不照搬其分数**，只借其“证据/扣分原因/补分动作”的结构，匹配排序由 §3 独立实现。
- 追问上限：其为每轮 ≤ 8 题；本项目取 ≤ 5（本项目的交互决策）。
- 每个借用的提示词文件在 `src/jobbot/llm/prompts/` 旁以 `PROVENANCE.md` 记录：来源路径、commit、修改点。

**导出要求**：单栏、标准标题、中文字体需可嵌入且许可证允许（WP-E 记录字体名与许可证）；PDF 可复制文字；导出后重新提取检查：页数、乱码、裁切、文字顺序。ATS 仅指结构检查，**不保证**特定招聘系统通过。

## 5. 数据集与标注

### 5.1 规模计划（pilot 级别，不是已有数据）

| 项目 | 目标 | 最低可接受 | 备注 |
|---|---|---|---|
| Profile | 项目负责人 + 2–4 位同学（不同方向） | 1（仅负责人） | 同学需**书面同意**并脱敏；只用于本课程；原简历不进仓库 |
| 岗位快照 | 200–300（4–6 个关键词，覆盖各 profile 的方向） | 100 | `source` 区分 boss / manual |
| 标注对 | 每 profile 60–80 | 每 profile 40 | 池化，见下 |
| 双人标注 | ≥ 20% 样本 | 若无第二标注者，间隔复标 ≥ 20% 并报告一致性 | 加权 κ（二次权重） |

仅 1 个 profile 时：只能报告“单用户排序”结果，用岗位分组 k 折；**不声称泛化到新用户**。

### 5.2 池化与盲标

对每个 profile，从全部岗位中取：B0 top-15、B1 top-15、B2 top-15（用锁定前的初始权重）、L0 top-15、随机 15、硬条件 fail 样本 5（取并集，约 50–80 个）。**不将 B3 纳入池**（B3 依赖标注，避免循环）；B3 的评估为在同一标注池上的重排序，限制写入报告（“池条件指标，不是全库召回”）。

标注界面：随机顺序；只显示 JD 原文、档案事实、偏好；**不显示任何模型分数/排名**。评分标准：

| rating | 含义 |
|---|---|
| 0 | 不合适（方向/硬条件明显不符） |
| 1 | 部分相关，关键条件待确认 |
| 2 | 基本合适，值得投递 |
| 3 | 高度合适，优先投递 |

另标 `hard_label`：pass / fail / unclear（地点、学历、经验等硬条件是否满足）及依据。同一 profile 的简历修订、同一岗位的近重复快照各自归为 `profile_group` / `job_group`，划分时不得跨分区。

### 5.3 划分与泛化对象

| 协议 | 说明 | 回答的问题 |
|---|---|---|
| **LOPO**（leave-one-profile-out） | 每次留出 1 个 profile 作测试，其余用于调权重/训练 B3 | 对**新用户**是否有效 |
| **Job-group k 折（k=5）** | 同一 profile 内按 job_group 分折 | 对**新岗位**是否有效（个性化） |

两者分别报告，不混用。划分种子、分组结果写 `split-manifest.json`。**先在训练部分选参数，再对留出部分跑一次，测试结果不回头调参。**

## 6. 实验清单

| ID | 目的 | 设计 | 主要指标 | 对应评分 |
|---|---|---|---|---|
| **E0** | 采集可靠性 | 采集会话日志：点击/捕获/解析数、字段非空率、薪资可读率、停止事件、每条耗时；模式 A 与 B 分开 | 捕获成功率（S1）、字段完整度、停止原因计数 | 工具/数据连接 |
| **E1** | 排序对比 | B0、B1、B2、B3、L0 在同一标注池；LOPO 与 job-group 折分别报 | NDCG@10、P@10、硬条件误放行/误杀、needs_review 比例、每 profile 单列 | ML 方法 |
| **E1a** | 消融 | 在 B2/B3 上去掉 `f_sem`、去掉 `f_skill`，各一次 | 同上 | 对照/消融 |
| **E2** | 抽取质量 | 简历：负责人对每条候选事实标 正确/部分/错误/幻觉，并列出漏抽；JD：抽 30 条人工检查要求类型、`inferred`误标为 hard 的次数 | 事实精确率、估计召回、引用有效率、JD 类型准确率、hard 误标数 | ML 方法/工具 |
| **E3** | 材料生成对照 | 20 个 JD × 条件：R0 原简历；R1 普通 LLM 润色；R2 完整流水线；R2-A 流水线但用最简自写提示（不用 rjo 提示词）；R2-B 流水线但关闭校验器。条件隐藏、顺序随机 | 无依据陈述率（**人工审计**为准）、重要要求覆盖率、盲评 1–5 分（负责人 + 1 位他人）、人工修改比例、调用数/耗时/成本 | Skills 复用消融 |
| **E4** | 效率 | 同一负责人筛选两组各 30 个 JD：一组纯人工（计时），一组用系统排序与解释（计时）；分组与顺序交换；记录决策与标注的一致程度 | 耗时、决策一致率；**n=1，仅描述性** | 需求价值 |
| **E5** | 校验器评估 | 构造集：对已确认事实生成的 40 条忠实陈述，施加 5 类扰动（数字改动、动词升级、新增无来源技能/工具、公司/日期替换、因果/个人贡献夸大）各 20 条 + 100 条未扰动对照，共 200 条；另收集 E3 中 R1 产出的自然错误作为次级集（人工标注）。方法：V0 规则；V1 规则+embedding；V2 规则+LLM 审查；V3 仅 LLM 判定 | 每类扰动的 P/R/F1、对照集误报率、调用成本；注明“合成扰动偏易” | ML 方法（分类） |

**不做**：真实外发申请的任何实验；重复向招聘方发消息获取样本。

## 7. 指标定义

- **NDCG@10**：增益 `2^rating − 1`，折扣 `1/log2(rank+1)`；标注池不足 10 条时用 `min(10, n)`；无相关项（所有 rating<2 或全 0）的查询单列，不并入均值（报告个数）。
- **P@10**：相关 = `rating ≥ 2`；候选 < 10 时分母 `min(10, n)`，单列该组。
- **硬条件误放行率**：`hard_label=fail` 的岗位中被判 `pass` 的比例；**误杀率**：`hard_label=pass` 中被判 `fail` 的比例；`needs_review` 比例另报。
- **校验器**：以“存在无依据陈述”为正类，报告 P/R/F1 与对照集误报率；分类型汇总。
- **无依据陈述率**：事实性陈述中无确认事实支持者 / 全部事实性陈述；无法解析样本计入失败率，不从分母删除。
- 模型自评分**不得**作为独立证据。LLM 审查只能辅助，不替代人工审计。
- 一致性：加权 κ（二次权重）；报告标注者数量与间隔。

## 8. 统计与产物

- 逐 profile 报告，宏平均仅作概括；置信区间用**按岗位重采样**的配对 bootstrap（每 profile 1000 次，种子固定），并注明 profile 数很少时区间只反映岗位抽样波动，不代表用户总体。
- 设计目标：B2/B3 的 NDCG@10 高于 B0 且硬条件误放行不恶化；批准版本的无依据陈述为 0；校验器召回 ≥ 0.8。**不达标也要写，并回退到已验证较好的方法**。
- 每次实验产出（`eval/results/<exp>/<date>_<commit>/`）：`dataset-manifest.json`（脱敏计数、来源、同意情况）、`split-manifest.json`、`model-manifest.json`（模型 ID/revision、提示模板哈希、sklearn 等版本）、`run-config.json`、`per-query-results.jsonl`（每 method×profile×job 一行：特征、分数、排名、标签）、`metrics.json`、`error-cases.md`、`env.json`（CPU/内存/OS/Python）。**必须能仅凭 `per-query-results.jsonl` 重算 `metrics.json`**（测试 T21）。

## 9. 误差分析流程

对 E1/E3/E5 的错误样本逐个归因，归入下列类别并计数：数据问题（JD 过短/缺要求/抓取错误）、抽取问题（要求类型或事实抽取错）、表示问题（embedding 对中英术语/缩写不敏感）、规则问题（硬过滤、别名）、提示问题（生成越权、格式）、标注歧义。每类给 ≥1 个例子（脱敏）、判断依据，并提出**一项有证据支持的改进**与改进后的重测结果，以及仍未解决的限制。

## 10. 威胁有效性（须在报告讨论中出现）

- 标注者即用户，存在偏好偏差；第二标注者仅覆盖部分样本。
- 池化只评估已标注池内的重排序能力，不等于全库召回。
- Profile 数极少，LOPO 的泛化结论很弱。
- 合成扰动集较易；自然错误样本量小。
- LLM 与 embedding 版本更换会改变结果；更换必须新建 manifest 并重跑，不覆盖旧结果。
- 采集的 JD 存在平台偏差（搜索排序、推荐机制），不代表整体岗位分布。
