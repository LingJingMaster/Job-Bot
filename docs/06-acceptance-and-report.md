# 验收、演示与报告

## 1. 验收原则

本文是**待执行**的测试协议；当前没有任何测试结果。`planned → passed` 须附日期、commit、配置、输入摘要、预期、实际、日志/截图路径、执行者。未运行记 `not_run`，被依赖阻塞记 `blocked`，失败记 `failed`。真实 Boss 采集与基于 fixtures 的逻辑测试**分开记录**：fixtures 通过只证明本系统逻辑，不证明 Boss 可用。

**发布阻断项**：存在向平台写入的路径；无依据陈述被批准或导出为终稿；Key/Cookie/真实简历/JD 原文进入公开仓库或提交物；实验结果无法由逐条文件重算；伪造或删改实验数据；新环境无法复现且未说明。一般视觉问题可记录后修，但不得影响材料阅读与事实核验。

## 4. 演示脚本（录屏 ≥ 1 次完整 + 1 次失败）

**完整运行**（约 6–8 分钟，标注“演示数据/真实采集”）：

1. 设置页：能力矩阵、LLM 配置掩码、采集器状态。
2. 上传简历 → 候选事实 → 确认/修改若干条（显示原文定位）。
3. 采集页：启动采集器（真实 Boss，登录后打开 3–5 个岗位）；运行记录显示捕获数。
4. 岗位与匹配页：运行 B2/B3；展示分组（pass / needs_review / fail）、分项得分、证据与缺口。
5. 选一个岗位 → 材料工作台：要求–证据表 → 回答 1–2 个追问 → 草稿 → Claim 校验 → 修改 → 批准 → 导出，并打开导出文件。
6. 申请跟踪页：手动标记“已投递”并关联材料版本。

**失败演示（至少一个）**：（a）在草稿里把“参与”改成“主导”→ 校验器拦截 → 批准按钮禁用；或（b）模拟采集遇到停止条件（用 fixtures 回放）→ 显示 `stop_reason` 与已保存数量。

录屏需看得出输入、关键步骤、最终结果；演示材料不能代替代码和实验记录。
